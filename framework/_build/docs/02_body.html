El reto de hoy

Cada activo nuevo duplica tus variables. Y si después cambias la fórmula del mid, la cambias en veinte sitios. El problema no es el tamaño: es que tu conocimiento vive copiado, no escrito una vez.

Hoy sales con dos armas: la función (una receta, N usos) y el book — una sola estructura donde viven todas las órdenes, con un equipo de funciones que la leen y la modifican.

~40 min lectura + práctica 7 secciones 3 simuladores lo cian se toca
§1 · La idea central

De copiar código a escribir recetas

Sigue bajando: el panel convierte el script duplicado en un libro de órdenes con su equipo de funciones. Es el mismo viaje que harás en el notebook.

0/5El diagnóstico

Mira el panel: la misma fórmula tres veces. Cada copia es un sitio donde equivocarse y un sitio que actualizar. Esto no escala a 20 activos — ni a 2 con prisa.

1/5La receta: def

Una función es una receta con huecos. La escribes una vez y la llamas N veces: compute_mid(99950, 100000), compute_mid(3400, 3402)…

Si después cambia la fórmula, la cambias en un sitio.

2/5Una fábrica de órdenes

make_order junta las dos ideas de L1 y L2: recibe los campos y devuelve el diccionario ya montado. Nunca más un dict a mano con una clave mal escrita.

3/5El book: un solo dato

Todas las órdenes viven en una lista. add_order(book, order) mete una nueva; el libro crece. Ya no hay bid_btc, bid_eth… hay un book.

4/5Leerlo: best bid, best ask, spread, mid

Las métricas de L1 vuelven, pero ahora son funciones que reciben el book y lo leen entero: el mejor comprador, el mejor vendedor, y el hueco entre ambos.

5/5Y una señal: el imbalance

¿Qué lado domina? imbalance(book) lo resume entre −1 y +1: negativo vende, cero equilibra y positivo compra.

Fíjate en el contador de abajo del panel: las 7 funciones reciben book. Guarda ese dato — es la pista de toda la semana.

§4 · Construye

    
Leer el libro: métricas y señal

    
Las funciones de lectura no tocan el libro — lo resumen.
    Componlas y tienes el cuadro de mandos de L1, ahora para N activos sin duplicar nada.


    
Sintaxis nueva · expresión generadora
      o['price'] for o in book if ... es un bucle compacto: produce un precio
      por cada orden que pasa el filtro. Sin corchetes no crea una lista; max,
      min o sum consumen esos valores uno a uno. Léela siempre en
      tres piezas: qué produce · de dónde sale · qué deja pasar.


    

      
order_book.py (lectura)python

      
def best_bid(book):    return max(o['price'] for o in book if o['side'] == 'buy')def imbalance(book):    buy_size  = sum(o['size'] for o in book if o['side'] == 'buy')    sell_size = sum(o['size'] for o in book if o['side'] == 'sell')    return (buy_size - sell_size) / (buy_size + sell_size)

§5 · Fija lo de hoy

    
5 preguntas

    

      

        
¿Qué devuelve make_order('BTCUSDT', 'buy', 99950, 0.5)?

        

          
          
          
        

        
Es una fábrica: recibe los campos y return el dict ya
        montado, siempre con las mismas claves.

      

      

        
book.append(order) — ¿qué le pasa a book?

        

          
          
          
        

        
append muta la lista original. Compáralo con la
        comprensión de cancel_order, que construye una nueva.

      

      

        
La comprensión [o for o in book if o['id'] != order_id]…

        

          
          
          
        

        
Filtra construyendo una lista nueva. El book viejo queda intacto —
        por eso la función hace return.

      

      

        
imbalance(book) devuelve +0.50. ¿Qué está diciendo el libro?

        

          
          
          
        

        
imbalance = (compra − venta) / total. Cero es equilibrio;
        +0.50 es presión compradora y +1 sería dominio comprador total.

      

      

        
Las 7 funciones de hoy comparten algo sospechoso. ¿Qué?

        

          
          
          
        

        
Un dato y el equipo de funciones que lo manosean, viajando siempre
        juntos… eso tiene nombre: objeto. Llega en L4.
