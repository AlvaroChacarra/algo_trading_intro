§1 · La idea central

La mudanza: de celdas a módulo

Sigue bajando: el panel muestra dos archivos. Tus funciones se mudan al de la izquierda; el de la derecha las usa sin saber cómo están hechas.

0/5Funciones atrapadas

Tus siete funciones viven en celdas de notebook. Solo existen mientras el kernel vive, y solo aquí. Nadie más puede usarlas — ni siquiera tú desde otro archivo.

1/5Nace order_book.py

La mudanza es literal: pegas las funciones en un archivo .py. Ya está. Un módulo es solo eso: un archivo de Python con cosas dentro.

2/5import order_book

Desde main.py, una línea trae el módulo entero. Sus funciones llegan con apellido: order_book.best_bid(book).

El prefijo te dice de dónde viene cada cosa — con 5 librerías importadas lo agradecerás.

3/5from order_book import imbalance

Si solo necesitas una función, la traes sin apellido y la llamas a pelo: imbalance(book).

Más cómodo, menos contexto. Los dos estilos son correctos; elige según cuánto importa saber el origen.

4/5Un archivo, dos vidas

El mismo order_book.py puede ser importado (librería) o ejecutado (python order_book.py). Python te chiva en qué modo está con la variable __name__.

5/5Una librería no revienta: avisa

¿best_bid de un libro vacío? Un módulo serio no devuelve basura ni muere con un error críptico: lanza un error tuyo, con tu mensaje. Eso es raise — y la otra mitad de la clase.

§2 · Simulador

¿Qué nombres te deja cada import?

La diferencia entre los dos estilos es qué nombres existen en tu archivo después de la línea. Alterna y compara:

simulador · el espacio de nombres de main.py


    


    
Regla práctica
    Módulo entero (import x o import x as alias) cuando usas
    varias cosas o quieres dejar claro el origen; from x import y cuando una
    función concreta se usa mil veces. Lo que no hacemos:
    from x import * — llena tu archivo de nombres que no sabes de dónde vienen.

5 preguntas

    

      

        
Tras import order_book, ¿cómo llamas a best_bid?

Solo trajiste ese nombre. El resto del módulo no existe en tu
        espacio de nombres.

      

      

        
Si el código dentro del try NO falla, el bloque except…

        

          
          
          
        

        
El except es la red: solo actúa si algo cae.

      

      

        
¿Para qué usa una librería raise ValueError("libro vacío…")?

        

          
          
          
        

        
Fallar claro es un regalo al usuario de tu librería (que serás tú
        en dos semanas). raise lanza; try/except caza.

      

      

        
__name__ == "__main__" es True cuando…

        

          
          
          
        

        
Ejecutado directamente → "__main__". Importado → el
        nombre del módulo. Por eso el bloque protege la demo.
