§2 · Construye

El libro que se deja preguntar

book.py — composición en 12 líneaspython
class OrderBook:    def __init__(self, bids, asks):        self.bids = bids  # lista de (price, size)        self.asks = asks    def best_bid(self):        return max(p for p, s in self.bids)    def best_ask(self):        return min(p for p, s in self.asks)    def mid(self):        return (self.best_bid() + self.best_ask()) / 2ob = OrderBook(bids=[(99950, 0.5), (99940, 0.2)],               asks=[(100000, 0.3), (100010, 0.15)])print(ob.mid())
Predice antes de ejecutar

Un método llamando a otros dos métodos del mismo objeto. ¿Qué imprime ob.mid()?

>>> 99975.0 # mid() usa self.best_bid() y self.best_ask() — los métodos se componen
Fíjate en la composición doble El objeto contiene datos (bids, asks) y los métodos se contienen entre sí: mid() llama a best_bid(). Cada pieza pequeña y comprobable — el estilo que mantiene vivo un sistema cuando crece.

§4 · La idea de diseño

Encapsulación: la puerta y la convención

Python no tiene candados de verdad — tiene convenciones que todo el mundo respeta. El guion bajo es la más importante.

portfolio.py — la puerta únicapython
class PositionTracker:    def __init__(self):        self._cash = 0.0        self._position = 0.0    def apply_fill(self, fill):        self._cash += fill.cash_flow()        if fill.side == 'buy':            self._position += fill.size        else:            self._position -= fill.size    def equity(self, mark):        return self._cash + self._position * mark
Honestidad tracker._cash = 10**9 funciona — Python no te lo impide. El guion bajo comunica el contrato: "si escribes aquí, la contabilidad deja de ser responsabilidad mía". Caja y posición deben moverse juntas (un fill toca ambas); la puerta única apply_fill lo garantiza, tocar a mano lo rompe.
