§1 · Construcción acumulativa de process()

Cada línea nace de un problema observable

El código de la izquierda se conserva y crece. El estado de la derecha cambia una sola vez por parada.

núcleo presencial

0/8La firma

La orden dice qué quiere el agente; el book contiene la liquidez. La función devuelve fills y muta ese mismo book.

núcleo presencial

1/8Elegir el lado contrario

Una BUY consume asks; una SELL consume bids. Cambia el toggle antes de mirar el código.

núcleo presencial

2/8¿Cuánto queda?

remaining empieza con el tamaño pedido. El loop termina cuando llega a cero o deja de haber niveles válidos.

núcleo presencial

3/8¿Cuánto tomo de este nivel?

take = min(remaining, level.size): nunca consumes más de lo pendiente ni más de lo disponible.

núcleo presencial

4/8¿Por qué no reducir ya?

Prueba la implementación ingenua: reduce cada nivel y solo al final descubre que una FOK no cabe.

Predice: ¿puede devolver [] y restaurar el book sin trabajo extra?

núcleo presencial

5/8Ahora nace planned

Guardamos pares (price, take) sin llamar a reduce. El plan responde qué ocurriría; todavía no lo ejecuta.

núcleo presencial

6/8Validar antes de mutar

Si una FOK no llena todo, return []. Como solo existía un plan, el libro sigue intacto.

núcleo presencial

7/8Commit

Solo tras validar, cada par del plan llama a book.reduce(consumed_side, price, take) y genera exactamente un Fill. consumed_side reutiliza la selección BUY→SELL / SELL→BUY de la parada 1.

consolidación requerida

8/8Política del remanente

LIMIT lo añade al libro. MARKET e IOC lo descartan. FOK ya habría abortado antes del commit.

La condición de cruce y la política final
LIMIT, IOC y FOK reutilizan el loop. La primera diferencia es si el precio cruza; la segunda, qué hacer con el remanente.

class MatchingEngine:    def process(self, order, book, timestamp=None):        opposite = book.asks if order.side is Side.BUY else book.bids        consumed_side = Side.SELL if order.side is Side.BUY else Side.BUY        remaining = order.size        planned = []        for level in opposite:            if remaining <= _EPS: break            if order.order_type is not OrderType.MARKET \                    and not self._crosses(order, level.price):                break            take = min(remaining, level.size)            planned.append((level.price, take))            remaining -= take        filled = order.size - remaining        if order.order_type is OrderType.FOK \                and filled < order.size - _EPS:            return []        fills = []        for price, take in planned:            book.reduce(consumed_side, price, take)            fills.append(Fill(order.id, order.symbol, order.side,                              price, take, timestamp))        if remaining > _EPS and order.order_type is OrderType.LIMIT:            book.add_limit(order.side, order.price, remaining)        return fills    @staticmethod    def _crosses(order, level_price):        if order.side is Side.BUY:            return order.price >= level_price        return order.price <= level_price
