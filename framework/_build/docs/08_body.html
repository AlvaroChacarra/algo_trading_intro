§1 · Anatomía de process()

Código y estado, sincronizados

Cada parada ejecuta una transición causal. El book no cambia hasta COMMIT.

0/6La firma

Entradas: orden y estado. Salidas: fills y el mismo estado mutado.

1/6Elegir el lado contrario

BUY ilumina asks; SELL ilumina bids. No hay cuatro motores.

2/6Inicializar remaining

Es la cantidad pendiente. Toda decisión del loop la reduce.

3/6take = min(...)

Tomas lo menor entre lo pendiente y lo disponible en el nivel activo.

4/6Planificar sin mutar

planned.append((price, take)). El OrderBook sigue intacto.

5/6Commit

reduce cambia el nivel y Fill registra el cruce.

6/6¿Qué hacemos con remaining?

La respuesta distingue MARKET, LIMIT, IOC y FOK.
