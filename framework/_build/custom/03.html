Clase 3 · El reto

Tu código está atrapado en el notebook.
Hazlo una librería.

La clase pasada escribiste `make_order`, `add_order`, `best_bid`, `imbalance`… pero viven sueltas en celdas. ¿Cómo las reutilizas en otro archivo sin copiar y pegar? ¿Y cómo evitas que un libro vacío te reviente el programa?

Hoy las metes en un módulo (`order_book.py`), lo importas, y lo blindas con try/except.

import order_book   order_book.spread(book)

El objetivo de hoy

Convertir tus funciones en una librería que importas desde cualquier sitio, y que no se cae con datos raros.

Esto es exactamente lo que harás con el paquete exchange desde la clase 7: import exchange. Hoy aprendes qué significa eso.
Bloque 1 · ¿Qué es un módulo?

Un módulo es un archivo .py con funciones

Guardas tus funciones en un archivo — ese archivo es un módulo. Aquí abajo tienes el contenido de order_book.py. Pulsa Guardar para crearlo de verdad (en el navegador), y en el siguiente bloque lo importaremos.

order_book.py
Bloque 2 · Importar

import order_book — y ya tienes tus funciones

Una vez guardado el módulo, lo importas y usas sus funciones desde otro código, sin copiar nada. Dos formas:

import order_book
trae el módulo entero. Usas order_book.spread(book).
from order_book import spread
trae solo lo que pides. Usas spread(book) directo.

Pulsa Ejecutar o Ctrl+Enter

Bloque 3 · ¿Por qué un módulo no se ejecuta al importarlo?

if __name__ == "__main__"

Cuando importas un módulo, Python ejecuta su código… pero tú no quieres que se ponga a imprimir cosas solo por importarlo. El truco: el código de prueba va dentro de if __name__ == "__main__":, que solo corre si ejecutas el archivo directamente, no al importarlo.

order_book.py (el módulo)
def spread(book): ...
solo define funciones. Importarlo no imprime nada.
main.py (el que se ejecuta)
import order_book
if __name__ == "__main__":
    main()
Regla práctica: el módulo define; el script con __main__ hace. En el notebook acabarás ejecutando un main.py que importa tu order_book.py.
Bloque 4 · Errores como red de seguridad

Que un dato raro no te tire el programa

`best_bid` sobre un libro vacío revienta (no hay máximo de nada). Una librería de verdad lo prevé: try/except atrapa el fallo y devuelve un plan B; raise lanza un error claro cuando el dato no tiene sentido.

Bloque 5 · El puente

Tienes una librería… pero datos y funciones siguen separados

Tu código ya es una librería robusta. Pero fíjate: el book (los datos) va por un lado, y las funciones (order_book.spread(book)) por otro — tienes que pasarle el libro a todo.

Hoy
order_book.spread(book)
la función y el dato, separados.
Las clases 4 y 5
book.spread()
el dato y su comportamiento, juntos: un objeto.
Juntar los datos con las funciones que los manosean en una sola cosa es la Programación Orientada a Objetos. Esas funciones de order_book.py se vuelven objetos: la orden (Order, clase 4) y el libro (OrderBook, clase 5).
