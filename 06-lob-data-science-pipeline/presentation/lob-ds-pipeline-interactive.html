Bloque 1 — 6 min

El pipeline: de datos a decisión

Un pipeline de ML tiene cinco etapas. Si fallas en cualquiera, el modelo puede parecer que funciona y en realidad no sirve para nada. Haz clic en cada etapa para ver los detalles.

📂
1. LOB Snapshot
500 snapshots de BTC. 41 columnas (10 niveles × bid/ask × precio/size + timestamp).
⚙️
2. Feature Eng.
mid, spread, imbalance, wmid, depth_ratio, spread_pct. De 41 columnas a 6 señales.
🎯
3. Target
¿mid sube o baja en t+1? Clasificación binaria. Más estable que predecir el precio exacto.
✂️
4. Split Temporal
Train: primeras 349 filas. Test: últimas 150. El test siempre está en el futuro.
📈
5. Baseline
El suelo mínimo: siempre UP, threshold, LogisticRegression. Si no lo superas, no sirve.
Bloque 2 — 6 min

Split temporal y data leakage

¿Por qué NO usar split aleatorio?

Train set

Test set

🔴

✓ El modelo nunca ve datos del futuro durante el entrenamiento. El test set representa condiciones inéditas.

Data Leakage: el feature que miente

Un feature que usa información del futuro produce resultados de evaluación perfectos — y falla en producción.

Feature candidato:
realized_spread = ask_price_1[t+1] − bid_price_1[t]

🔴 ask_price_1[t+1] es el ask price del siguiente snapshot.
En el momento de la predicción (t), ese precio todavía no existe.

El modelo aprende a predecir el pasado usando información del futuro.

Sin leakage
~49%
Con leakage
???

Si añadir un feature mejora la accuracy de forma inesperada, pregúntate:
¿este dato existía en el momento t?

Bloque 3 — 5 min

Baseline: el suelo mínimo

Un baseline es lo que obtienes sin esfuerzo. Si tu modelo sofisticado no lo supera, vuelve al paso 2.

Cierre

3 ideas para llevarse

⚙️
Pipeline primero
Un modelo potente con pipeline roto produce basura. La arquitectura es el modelo.
⏱️
Split respeta el tiempo
train_test_split con shuffle=True es un error en series temporales.
🔍
Baseline antes que modelo
Si no superas el baseline, vuelve a los features. No al modelo.
⚠️
Sospecha del salto de accuracy
+35pp de golpe al añadir un feature = leakage. Siempre.
🎯
54% es el punto de partida
Honesto, sin trampas. L7 lo mejora con más features y más modelos.
