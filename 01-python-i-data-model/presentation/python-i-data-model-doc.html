De texto a máquina

Delante tienes el libro de órdenes de BTCUSDT. Compradores abajo, vendedores arriba, y un hueco en medio. La pregunta más básica de todo el trading electrónico: ¿cuánto vale esto ahora mismo?

El reto de hoy

El mejor comprador paga 99950. El mejor vendedor pide 100000. El punto medio — el mid — es la respuesta más honesta a "cuánto vale".

Tú lo calculas de cabeza. Pero una máquina solo entiende 1s y 0s, y tú solo sabes escribir texto. Al final de este documento habrás cruzado esa distancia: un programa en Python que lee un libro, calcula el mid y decide qué hacer.

§1 · La idea central

Python es un programa que lee tu texto

Vas a escribir mid = (bid + ask) / 2. Eso es texto. La CPU no entiende texto. Entre tu línea y la máquina hay un viaje de cuatro paradas — y verlo una vez hace que los errores de Python dejen de parecer magia negra. Sigue bajando: el panel de la derecha va transformando tu línea en cada parada.

0/5Esto es todo lo que Python recibe

Una línea de texto. Para Python, de momento, no significa nada: son 30 caracteres, igual que un mensaje de WhatsApp.

1/5Tokenizar: trocear el texto

Primera parada: Python corta la línea en piezas con etiqueta — tokens. mid es un nombre, = un operador, 2 un número.

Como separar palabras y puntuación en una frase, antes de intentar entenderla.

2/5El árbol (AST): poner orden

Los tokens en fila no dicen qué se hace antes. Python los organiza en un árbol: la suma cuelga de la división, la división cuelga de la asignación.

Fíjate: el paréntesis que escribiste ya no existe — su trabajo era dar forma al árbol, y el árbol ya la tiene.

3/5Bytecode: la receta plana

El árbol se aplana en instrucciones simples y ordenadas: carga bid, carga ask, suma, carga 2, divide, guarda en mid.

Esto ya no es para ti. Es para la máquina virtual de Python.

4/5La VM ejecuta, instrucción a instrucción

La máquina virtual recorre el bytecode con una pila: apila valores, los combina, guarda el resultado. Míralo correr a la derecha.

Cada programa Python que has visto en tu vida acaba siendo exactamente esto.

5/5Y abajo del todo: 1s y 0s

La VM es a su vez un programa (escrito en C) que la CPU ejecuta como binario. La distancia texto → máquina está cruzada.

Y mid ya existe: vale 99975.0.

Honestidad Esto es una simplificación fiel: CPython real hace más cosas (cachea el bytecode en .pyc, optimiza, gestiona memoria). Pero tokenizar → árbol → bytecode → VM es el esqueleto real, y es todo lo que necesitas para razonar sobre tus errores.

¿Y por qué así? Dos formas de salvar la distancia

Compilador

Traduce todo el texto a binario antes de ejecutar. Rápido corriendo, lento iterando. (C, Rust)

Intérprete puro

Lee y ejecuta línea a línea. Cómodo, pero repite trabajo todo el rato.

Python: híbrido

Compila a bytecode una vez y la VM lo interpreta. Por eso itera rápido — ideal para investigar mercados.

Variables: nombres que apuntan a valores

    
Ya sabes qué hace Python con tu texto. Ahora escríbelo de verdad.
    Una variable no es una "caja": es un nombre que apunta a un valor.
    Cuatro líneas y el reto de la portada queda resuelto.

¿Y ese .0?
      Escribiste números enteros pero salió 99975.0. La división / en Python
      siempre devuelve un float (número con decimales), aunque el
      resultado sea redondo. Si tu predicción fue 99975, acabas de aprender la
      diferencia entre int y float — mejor que con cualquier definición.

§3 · Construye

    
Listas y for: cuando no tienes un dato, sino muchos

    
Un mercado no te da un precio: te da un chorro de precios.
    Guardarlos de uno en uno (p1, p2, p3…) no escala.
    Una lista los guarda juntos y un for los recorre.


    

      
media.pypython

      
prices = [99950, 99975, 100010, 99990]total = 0for p in prices:    total = total + pmedia = total / len(prices)

    


    
La jugada tiene dos piezas: el acumulador (total empieza en 0
    y va engordando) y el cursor (p toma cada valor de la lista, por
    turno). Ejecuta el bucle vuelta a vuelta:

§4 · Construye

    
Diccionarios: una orden de verdad

    
Una orden real no es un número suelto: es lado + precio + tamaño
    viajando juntos. La lista guarda cosas por posición; el diccionario las guarda
    por nombre. Pasa el ratón por el código o por la ficha — son la misma cosa
    vista dos veces.

§5 · Construye

    
if / elif / else: convertir un dato en una decisión

    
Hasta aquí, tu programa describe el mercado. Un algoritmo de trading
    además decide. La estructura es un embudo: Python prueba condiciones en orden
    y ejecuta solo la primera que se cumple.


    

      

        spread = 50
        
      

      

        
if spread < 20:    decision = "líquido: cruzar ya"elif spread < 80:    decision = "aceptable: limit al mid"else:    decision = "ilíquido: esperar"

      

      
decision = "aceptable: limit al mid"

    


    
Mueve el slider y fíjate en dos cosas: solo una rama se ilumina cada vez,
    y el orden importa — con spread = 10 ambas condiciones son ciertas, pero gana la
    primera.


    
Honestidad
    Los umbrales 20 y 80 me los he inventado para la demo. Elegirlos bien es un problema de
    trading (lo trabajaremos); la estructura del embudo es el problema de hoy,
    y esa ya es tuya.

§7 · El clímax

    
Dato → cálculo → decisión

    
Todo junto. Un diccionario con el libro (dato), el spread y el mid (cálculo),
    y el embudo que decide (decisión). Esto — quince líneas — ya es un algoritmo de
    trading: primitivo, pero con la misma anatomía que uno profesional.


    

      
primer_algoritmo.pypython

      
# 1 · DATObook = {"bid": 99950, "ask": 100000}# 2 · CÁLCULOspread = book["ask"] - book["bid"]mid = (book["ask"] + book["bid"]) / 2# 3 · DECISIÓNif spread < 20:    decision = "líquido: cruzar ya"elif spread < 80:    decision = "aceptable: limit al mid"else:    decision = "ilíquido: esperar"print("mid:", mid)print("spread:", spread)print("decisión:", decision)
