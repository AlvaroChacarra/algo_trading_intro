Bloque 1 · ¿Qué es Python?

Python es un programa que lee tu texto

Tu archivo .py no es mágico: es texto plano, como un .txt. "Python" es otro programa (se llama CPython) instalado en tu ordenador, cuyo trabajo es leer ese texto y hacer que ocurra.

tu_archivo.py — solo texto
bid = 99950 ask = 100000 mid = (bid + ask) / 2 print(mid)
Si desinstalas Python, este archivo sigue existiendo… pero ya no hay nadie que lo lea. Como una partitura sin músico.
qué hace Python con él
📄 1 · Lee el texto, de arriba abajo
🔎 2 · Lo entiende (lo traduce a instrucciones)
▶ 3 · Lo ejecuta y produce un resultado

Ese paso 2 —"entenderlo"— es lo interesante. Y ahí está la pega: la máquina, por debajo, no entiende ni letras ni palabras.

Bloque 1 · ¿Qué es Python?

Una máquina solo entiende 1s y 0s

Un procesador es millones de interruptores: encendido (1) o apagado (0). No conoce la letra b ni la palabra bid. Cada carácter de tu archivo es, por debajo, un número, y ese número es una secuencia de bits.

Escribe texto y míralo en binario
la pega

Convertir las letras a bits es fácil. Pero eso no es ejecutar el programa: la máquina aún no sabe que bid + ask significa "suma estos dos números".

Hace falta traducir el significado de tu código, no solo sus letras. De eso va el resto de la clase: el viaje de mid = (bid + ask) / 2.
Texto→Tokens→AST→Bytecode→VM → 1s/0s
Bloque 2 · El viaje de tu línea

Paso 1 — Tokenizar: trocear el texto

Lo primero que hace Python es partir tu línea en piezas con significado, los tokens: nombres, operadores, números. Igual que tú lees "(bid + ask)" y ves cuatro cosas, no doce letras.

mid = (bid + ask) / 2  se convierte en:

midname
=op
(op
bidname
+op
askname
)op
/op
2number
Un nombre (name) apunta a un valor; un operador (op) hace algo; un número es un valor literal. Todavía no se calcula nada — solo se han identificado las piezas.
Texto→Tokens→AST→Bytecode→VM → 1s/0s
Bloque 2 · El viaje de tu línea

Paso 2 — El árbol (AST): poner orden

Las piezas sueltas no bastan: hay que saber qué se opera con qué. Python las organiza en un árbol que captura la estructura. Aquí se ve que primero se suma bid + ask y luego se divide entre 2 (por los paréntesis).

El árbol, dibujado
asignar a mid └─ / (dividir) ├─ + (sumar) │ ├─ bid │ └─ ask └─ 2
Se lee de dentro afuera: suma bid+ask, divide el resultado entre 2, guarda en mid.

Bloque 2 · El viaje de tu línea

Paso 3 — Bytecode: instrucciones para la máquina virtual

Del árbol, Python genera una lista de instrucciones simples — el bytecode. Son las órdenes que ejecutará la máquina virtual de Python, una a una, como una receta.

Qué dice el bytecode (en cristiano)
LOAD_NAME bid# coge el valor de bid
LOAD_NAME ask# coge el valor de ask
BINARY_OP +# súmalos
LOAD_CONST 2# coge el número 2
BINARY_OP /# divide
STORE_NAME mid# guarda el resultado en mid
El bytecode real (dis)
Pulsa "Ver bytecode" para el desensamblado real que ejecuta la VM.
Texto→Tokens→AST→Bytecode→VM → 1s/0s
Bloque 2 · El viaje de tu línea

Paso 4 — La VM ejecuta, y abajo del todo: 1s y 0s

La máquina virtual de Python lee el bytecode instrucción a instrucción. Cada una se traduce, ya sí, en operaciones reales de la CPU — sumar, dividir, mover datos — que son 1s y 0s. Ahí se cierra el viaje.

📄 tu texto: mid = (bid + ask) / 2
⇩ tokens → árbol (AST) → bytecode
🐍 la VM ejecuta el bytecode, instrucción a instrucción
01 cada instrucción → operaciones binarias en la CPU → resultado: 99975.0
Recuerda: compilar = tu texto → bytecode. Interpretar = la VM ejecutando ese bytecode. Python hace las dos. Lo vemos en el siguiente bloque.

Bloque 3 · Compilar vs interpretar

Dos formas de salvar la distancia texto → máquina

Acabas de ver que Python convierte tu texto en bytecode. Pero no todos los lenguajes funcionan igual. Hay dos grandes familias.

Compilado — p.ej. C

📄 escribes el código fuente
⚙️ un compilador lo traduce entero a binario, una vez
01 queda un ejecutable en binario puro de esa máquina
▶ la CPU lo ejecuta directo — muy rápido
Pega: hay que compilar antes de ejecutar, y el binario solo sirve para ese tipo de máquina. Nada de probar línea a línea.
Bloque 3 · Compilar vs interpretar

Python es híbrido: compila a bytecode y lo interpreta

Python no traduce todo a binario de golpe. Compila tu texto a bytecode (lo que viste) y una máquina virtual lo interpreta sobre la marcha. Más lento que C, pero portable e interactivo — puedes probar línea a línea.

Interpretado — Python

📄 tu texto .py
⚙️ Python lo compila a bytecode (rápido, automático)
🐍 la máquina virtual lee el bytecode…
▶ …y lo ejecuta instrucción a instrucción
Por eso Python es genial para aprender y prototipar (y para Jupyter): compila y ejecuta al vuelo. Ese equilibrio es justo lo que lo hace cómodo para trading.

Bloque extra · Los errores son pistas

Rompe código a propósito

Ahora que conoces el viaje, los errores tienen sentido. Un SyntaxError es que Python no pudo ni compilar tu texto a bytecode. Un error de ejecución (NameError, TypeError…) es que compiló, pero la VM tropezó al ejecutarlo.

🔧 Reto 1: Paréntesis perdidoSin resolver

Falla al compilar: Python no entiende la estructura. Arréglalo.

SyntaxError (fase de compilación) — cuenta los paréntesis: ¿cuántos abren y cuántos cierran?
🔧 Reto 2: Variable fantasmaSin resolver

Compila bien, pero la VM no encuentra algo al ejecutar. ¿Qué falta?

NameError (ejecución) — ask no existe. Defínela antes de usarla.
🔧 Reto 3: Tipos incompatiblesSin resolver

Todo existe, pero la operación no tiene sentido. ¿Por qué falla?

TypeError (ejecución) — price es texto. Quita las comillas para que sea un número.
🔧 Reto 4: División imposibleSin resolver

Correcto... hasta que los números no cuadran. ¿Cómo lo arreglas?

ZeroDivisionError (ejecución) — total es 0. Verifica antes de dividir.
