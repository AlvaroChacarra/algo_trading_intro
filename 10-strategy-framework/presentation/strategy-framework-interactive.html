El framework: Strategy + Backtest

El corazón del curso: una estrategia solo reacciona al libro y devuelve acciones. El Backtest la cablea con el mercado y el portfolio. Cualquier estrategia se enchufa igual.

Hoy construyes: interfaz Strategy (ABC) y el runner Backtest
Bloque 1

La interfaz Strategy

Una estrategia implementa on_book_update(book) y devuelve una lista de acciones (NewOrder/Cancel). No sabe nada del motor. Esa ignorancia es lo que la hace enchufable.

class Strategy(ABC):
    @abstractmethod
    def on_book_update(self, book) -> list[Action]:
        ...
Bloque 2

Acciones, no efectos

La estrategia no ejecuta órdenes: las pide. Devuelve NewOrder(order). El Backtest decide qué hacer con ellas. Separar decisión de ejecución es la clave del diseño.

return [NewOrder(Order('BTC', Side.BUY, 0.1,
        order_type=OrderType.MARKET))]
Bloque 3

El Backtest lo cablea todo

Recorre el mercado, pasa cada libro a la estrategia, ejecuta sus acciones contra el matching, actualiza el portfolio y mide. El mismo run() para cualquier estrategia.

result = Backtest(market, mi_estrategia).run()
result.final_equity, result.n_fills
Cierre

Escribe una subclase de Strategy y enchúfala al mismo Backtest. Eso es polimorfismo, y es lo que hace todo modular.
